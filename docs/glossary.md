## Данные и загрузки

| Термин | Значение и пример |
|---|---|
| <a id="term-raw"></a>Raw | Первый слой озера: данные источника без бизнес-преобразований, с техническими отметками загрузки |
| <a id="term-entity"></a>Сущность | Таблица источника, описанная в конфигурации загрузки. Например, `retail_bank.transactions` |
| <a id="term-fqn"></a>FQN | Полное имя таблицы источника: `<схема>.<таблица>`. Например, `retail_bank.transactions` |
| <a id="term-manifest"></a>Манифест | Файл с описанием источника или набора загрузок. Для загрузчика это YAML-файл |
| <a id="term-pipeline"></a>Пайплайн (pipeline) | Набор загрузок одного источника, описанный одним YAML-файлом |
| <a id="term-full"></a>Полный срез (full) | Чтение всей таблицы источника и добавление результата в историю raw. Не заменяет ранее записанные строки |
| <a id="term-snapshot"></a>Таблица-снимок (act_snap) | Вспомогательная таблица полного состояния источника для raw-таблицы с инкрементальной загрузкой. Её DAG генерируется только вместе с инкрементальной конфигурацией, но может запускаться независимо от основной загрузки и не меняет её watermark. Непустой результат атомарно заменяет `__act_snap`, пустое чтение сохраняет существующую таблицу |
| <a id="term-ods"></a>ODS | Планируемый слой устранения повторов и построения состояния записей поверх raw |
| <a id="term-dds"></a>DDS | Планируемый слой структурированных данных предметной области |
| <a id="term-dma"></a>DMA | Планируемый слой витрин для потребителей данных |

## Запуски и повторные попытки

| Термин | Значение и пример |
|---|---|
| <a id="term-dagrun"></a>DagRun | Запуск DAG-а с определённым `run_id` |
| <a id="term-execution"></a>Исполнение | Выполнение DAG-а с одним `process_id`. Повтор генератора идентификатора создаёт новое исполнение внутри того же DagRun |
| <a id="term-batch"></a>Партия загрузки | Загрузка одной сущности в одном исполнении. Ключ: `(process_id, source_id, entity_fqn)`. Повтор `load` сохраняет партию |
| <a id="term-attempt"></a>Попытка | Одно выполнение загрузки партии. Повтор задачи `load` — новая попытка той же партии |
| <a id="term-portion"></a>Порция | Строки, записанные одной попыткой загрузки. Имеют общие `__process_id` и `__load_dttm` |
| <a id="term-retry"></a>Retry | Автоматический повтор задачи Airflow. Повтор `load` сохраняет `process_id`, повтор `generate_process_id` выделяет новый номер |
| <a id="term-clear"></a>Clear | Сброс состояния выбранных задач в Airflow для повторного выполнения. Не удаляет данные озера и pg-meta |
| <a id="term-asset"></a>Asset | Именованный набор данных Airflow. Событие его обновления может запускать зависимые DAG-и |
| <a id="term-ttl"></a>TTL | Время работы активированного источника до автоматической остановки |

## Инкрементальная загрузка

| Термин | Значение и пример |
|---|---|
| <a id="term-increment"></a>Инкремент (incremental) | Загрузка строк из очередного диапазона значений выбранной колонки источника |
| <a id="term-position"></a>Позиция инкремента | Значение колонки, по которой выбирают очередные строки. Например, `_batch_id=11` |
| <a id="term-canonical"></a>Канонический тип / вид позиции | Единое для разных СУБД описание типа / формат записи значения. Тип задаёт диапазон, точность и временную семантику. Например, `timestamp_instant(7)` / момент в UTC с семью цифрами дробной секунды |
| <a id="term-watermark"></a>Watermark | Сохранённый максимум позиции после успешной загрузки. Следующее окно отсчитывается от него. Не доказывает, что все меньшие значения уже загружены |
| <a id="term-window"></a>Окно | Диапазон позиций для чтения. Например, `10 < _batch_id AND _batch_id <= 11` |
| <a id="term-lookback"></a>Lookback | Отступ назад от watermark для повторного чтения части предыдущих значений |
| <a id="term-bootstrap"></a>Bootstrap | Первичное наполнение инкрементальной таблицы, когда сохранённого watermark ещё нет |
| <a id="term-cas"></a>CAS / CAS revision | Compare-and-set: запись результата только при совпадении текущей и ожидаемой версии состояния. Если состояние изменилось, запись отклоняется |

## Хранение и гарантии

| Термин | Значение и пример |
|---|---|
| <a id="term-bucket"></a>Бакет (bucket) | Контейнер объектов в S3-хранилище, аналог верхнего уровня каталога файлов |
| <a id="term-iceberg-snapshot"></a>Snapshot Iceberg | Версия таблицы после коммита. Не то же самое, что полный срез источника или отдельная таблица `__act_snap` |
| <a id="term-rtas"></a>RTAS | `CREATE OR REPLACE TABLE ... AS SELECT`: атомарная замена таблицы результатом запроса |
| <a id="term-append"></a>Append-only | Новые строки дописываются, ранее загруженные не заменяются |
| <a id="term-atleast"></a>At-least-once | При восстановлении после сбоя строки могут записаться повторно |
| <a id="term-exactly"></a>Exactly-once | Однократная запись без дублей при повторном выполнении. Текущий raw-загрузчик такой гарантии не даёт |
| <a id="term-idempotency"></a>Идемпотентность | Повтор операции даёт тот же итог, что и однократное выполнение |
| <a id="term-fencing"></a>Fencing | Запрет старому исполнителю записывать результат после потери права на запись |

## Вычисления и ресурсы

| Термин | Значение и пример |
|---|---|
| <a id="term-driver"></a>Driver | Управляющий процесс Spark-приложения. Не путать с JDBC-драйвером подключения к СУБД |
| <a id="term-executor"></a>Executor | Рабочий процесс Spark, выполняющий задачи обработки и записи данных |
| <a id="term-jdbc-partition"></a>JDBC-партиция | Часть исходной выборки, которую Spark читает отдельным SQL-запросом |
| <a id="term-pool"></a>Пул (pool) | Ограничитель допуска задач Airflow к выполнению. Не выделяет CPU и память |
| <a id="term-slot"></a>Слот (slot) | Единица ёмкости пула Airflow. Задача может занимать несколько слотов. В описании executors слово «слот» означает место для одновременного выполнения Spark-задачи |
| <a id="term-job"></a>Job / stage / task | Вычисление Spark / его стадия / задача обработки одной партиции. Не путать Spark task с задачей Airflow |
| <a id="term-shuffle"></a>Shuffle | Перераспределение данных между задачами Spark по сети и через диск |
| <a id="term-spill"></a>Spill | Выгрузка промежуточных данных Spark на диск при нехватке памяти |
| <a id="term-udf"></a>UDF | Пользовательская функция для обработки данных в Spark |
| <a id="term-rdd"></a>RDD | Распределённая коллекция данных в низкоуровневом API Spark |

| Термин | Значение и пример |
|---|---|
| <a id="term-runtime"></a>Runtime-проверка | Проверка на работающей системе, а не только чтение кода |
