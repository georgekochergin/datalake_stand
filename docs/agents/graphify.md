## 1. Назначение

**graphify** строит граф кодовой базы (файлы, символы, зависимости между ними)
и отвечает на вопросы по нему консольными командами, не читая файлы целиком.
Граф используется агентом при анализе кода: поиск, навигация по зависимостям,
оценка влияния изменений — это сокращает расходы на LLM-анализ репозитория.

### Результат настройки

После настройки команда полного перестроения

```bash
. ~/.config/graphify/env && graphify extract . --backend openai && graphify cluster-only
```

должна выполняться без ручной подготовки.
Выбор способа обновления описан в [разделе 4](#4-перестроение-графа).
Правила агента — в [AGENTS.md](../../AGENTS.md).

Результат — `graphify-out/graph.json` в корне репозитория:

- В нём находятся узлы, связи и имена сообществ.
- После `git pull` можно сразу выполнять запросы, без перестроения и ключей API.
- Остальные файлы `graphify-out/` в git не попадают.

## 2. Установка утилиты

Установите утилиту через **pipx**. Он создаёт изолированное Python-окружение
и размещает команду `graphify` в `~/.local/bin`.
Активировать отдельный `venv` при каждом запуске не потребуется.

```bash
brew install pipx
pipx ensurepath
pipx install 'graphifyy[openai,sql]'
```

Обратите внимание: пакет на PyPI называется `graphifyy` (с двойной `y`),
устанавливаемая команда — `graphify`. Дополнение `openai` — доступ к
OpenAI-совместимому API, `sql` — разбор SQL-файлов (в репозитории есть
SQL и YAML, они обрабатываются всегда).

После установки перезапустите оболочку (или выполните `source ~/.zshrc`),
чтобы `~/.local/bin` попал в `PATH`. Проверка: `graphify --version`.

## 3. Переменные окружения

Ключи хранятся **вне репозитория** — в `~/.config/graphify/env`, чтобы их
нельзя было случайно закоммитить. Файл нужен только при перестроении графа.
запросы по готовому графу ключей не требуют.

```bash
mkdir -p ~/.config/graphify
cat > ~/.config/graphify/env <<'EOF'
export OPENAI_API_KEY="вставьте_ключ"
export OPENAI_BASE_URL="https://api.z.ai/api/coding/paas/v4"
export OPENAI_MODEL="glm-5.3"
EOF
chmod 600 ~/.config/graphify/env
```

| Переменная | Обязательна | Назначение |
|---|---|---|
| `OPENAI_API_KEY` | да | Ключ API. Без него семантическое извлечение и кластеризация не выполняются |
| `OPENAI_BASE_URL` | да | Адрес OpenAI-совместимого API (поддерживаются и внешние сервисы, и self-hosted серверы) |
| `OPENAI_MODEL` | да | Имя модели для семантического извлечения и именования сообществ |

Префикс `OPENAI_` обозначает совместимость с протоколом, а не поставщика модели.

- `--backend openai` использует адрес и ключ выбранного OpenAI-совместимого сервиса.
  В примере указан z.ai (GLM).
- Используется только `chat/completions`. API Embeddings не нужен.
- Для Anthropic-совместимого шлюза используется `--backend claude`
  и переменные `ANTHROPIC_BASE_URL`, `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`.

Агент подключает файл командой `. ~/.config/graphify/env` перед запуском
`extract` (переменные не глобальные, живут в рамках команды).

## 4. Перестроение графа

Решение о перестроении принимается перед каждым коммитом анализом включаемых изменений:

| Ситуация в коммите | Действие | Стоимость |
|---|---|---|
| Менялись только тексты существующих документов (`.md`), `.gitignore`, сам `graphify-out/` | ничего не делать | — |
| Код менялся типово: правки внутри существующих модулей, тесты, конфиги, переименования.<br>Структурные изменения документации — новые, переименованные или перемещённые файлы (graphify индексирует и документы) | `graphify update .` (при массовых удалениях кода — с `--force`) | нет: локально, без LLM, токен не нужен |
| Семантически значимые изменения: граф отсутствует (первичное построение), новые модули или контракты между компонентами, крупный рефакторинг с переносом логики между слоями | `. ~/.config/graphify/env && graphify extract . --backend openai && graphify cluster-only` | LLM-API (платно) |

- Если нужен запуск с LLM, а `~/.config/graphify/env` не настроен:
  - Агент сообщает об этом пользователю и выполняет локальный `update` как фоллбэк.
  - В описании PR указывается, что семантический слой не перестроен.
- Обновлённые `graphify-out/graph.json` и `graphify-out/GRAPH_REPORT.md` включаются в тот же коммит, что и соответствующие изменения:
  - Не откладывается до завершения PR.
  - Подробный порядок — в [скилле graphify](../../.agents/skills/graphify/SKILL.md) и скилле `pull-request`.
- `extract` обрабатывает новые и изменённые файлы. Неизменённые определяются по хэшам из `manifest.json` и пропускаются.
- После `update` имена сообществ пересчитываются локально по наиболее связанным узлам.
  Если сохранён кэш названий, `cluster-only` использует его и игнорирует `--backend`.
  Для полного переименования с помощью модели используется
  `graphify label . --backend=openai` в окружении с настроенным API.

### Защита от сокращения семантического графа

`extract` может отказаться перезаписывать граф с сообщением
`unverified semantic shrink`, даже если все запросы к модели завершились.
Защита сравнивает число семантических узлов каждого документа с прежним графом.
Уменьшение числа узлов само по себе не доказывает обрезанный ответ:
документ мог стать короче или перестать описывать удалённые компоненты.

Перед повтором:

1. Проверить лог на ошибки API, незавершённые блоки и обрезанные ответы.
2. Сопоставить прежние узлы, новый результат в `graphify-out/cache/semantic/`
   и актуальный документ. Подтвердить, что сокращение не теряет нужные сущности.
3. Убедиться в наличии резервной копии прежнего графа.
4. Только для проверенного сокращения повторить
   `graphify extract . --backend openai --allow-partial`, затем
   `graphify cluster-only . --backend=openai` в окружении с настроенным API.
5. Проверить итоговый граф запросами и просмотреть `GRAPH_REPORT.md`.

`--allow-partial` не является обычным параметром обновления: он снимает защиту
от неполного извлечения. Не добавлять его к штатной команде автоматически.

Если граф пропущен в уже созданном коммите, он актуализируется отдельным
коммитом без переписывания истории. Коммит только графа повторного
перестроения не требует.

## 5. Артефакты `graphify-out/` и git

В git отслеживаются `graphify-out/graph.json` и `graphify-out/GRAPH_REPORT.md`.
Все команды раздела 6 работают по одному `graph.json`. Отчёт нужен для просмотра
результатов анализа и обновляется при кластеризации. Правило в `.gitignore`:

```gitignore
graphify-out/*
!graphify-out/graph.json
!graphify-out/GRAPH_REPORT.md
```

| Артефакт | В git | Назначение |
|---|---|---|
| `graph.json` | да | Сам граф: узлы, рёбра, имена сообществ внутри узлов |
| `.graphify_labels.json` (+ `.sig`) | нет | Кэш кластеризации: стабильность номеров/имён сообществ между пересборками.<br>Запросам не нужен |
| `.graphify_analysis.json` | нет | Вход повторной кластеризации (`cluster-only`) и отчётов |
| `manifest.json` | нет | Кэш инкрементальности (хэши файлов): без него очередное `extract` просто просканирует всё заново |
| `GRAPH_REPORT.md` | да | Отчёт по графу, регенерируется кластеризацией |
| `graph.html` | нет | Производная визуализация, регенерируется кластеризацией |
| `cache/`, `<дата>/` | нет | Семантический кэш и снимки запусков |
| `cost.json`, `memory/`, `reflections/` | нет | Учёт расходов API и петля обратной связи (`save-result`/`reflect`) |
| `.graphify_root`, `.graphify_semantic_marker`, `.cloud-cta-shown` | нет | Служебные метки утилиты |

## 6. Запросы по графу

Все команды работают офлайн, ключи API не нужны. Граф по умолчанию —
`graphify-out/graph.json`.

| Команда | Назначение |
|---|---|
| `graphify query "<вопрос>"` | Обход графа по вопросу.<br>`--budget N` — лимит токенов вывода (по умолчанию 2000).<br>`--seed X` — старт с заданного узла |
| `graphify explain "<узел>"` | Узел и его связи (`--all` — все связи, по умолчанию 20 самых связных) |
| `graphify path "A" "B"` | Кратчайший путь между двумя узлами |
| `graphify affected "X"` | Обратный обход: что зависит от X (оценка влияния изменения) |
| `graphify god-nodes` | Самые связные узлы (архитектурные центры) |

Коды возврата:

- `0` — ответ найден.
- `3` — имя неоднозначно. Команда перечислит кандидатов.
- `4` — узел не найден.
