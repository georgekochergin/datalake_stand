<a id="сценарии"></a>
## Пользовательские сценарии и проверки

### Сценарий 1. Верхняя граница только по окну чтения (P1)

Сопровождающий запускает регулярную загрузку большой таблицы. Чтобы определить верхнюю границу, загрузчику не нужно рассчитывать максимум по всей истории или подсчитывать строки. Это основное упрощение для регулярных запусков.

**Независимая проверка**: загрузить таблицу с уже сохранённой позицией и проверить запрос определения верхней границы и результат загрузки.

1. При нулевом [lookback](../../docs/glossary.md#term-lookback) значение, равное сохранённой позиции, не входит в выборку. При ненулевом временном отступе значение, равное выровненной нижней границе, входит.
2. Если нижнему условию не соответствует ни одна строка, загрузка завершается успешно без записи данных и без изменения сохранённой позиции.
3. Если максимум среза ниже сохранённой позиции, загрузчик читает только строки внутри рассчитанных границ. Например, при сохранённой позиции `100` и целочисленном отступе `10` запрос ищет максимум среди строк с `id > 90`. Если нашёл `97`, загрузчик читает `90 < id <= 97` и оставляет сохранённую позицию равной `100`.
4. Если колонка допускает `NULL`, новая загрузка по умолчанию отклоняется даже при отсутствии фактических `NULL`. При явном `incremental.contract.check_not_null: false` отсутствие подтверждения `NOT NULL` не блокирует загрузку.

### Сценарий 2. Последняя ступень разбиения — дата (P2)

Сопровождающий может предсказать режим чтения по схеме таблицы. Ради параллелизма загрузчик больше не вычисляет номера календарных дней из временных отметок.

**Независимая проверка**: загрузить таблицу, у которой единственный прежний кандидат — `timestamp NOT NULL`, со строками за несколько дней. Чтение идёт одним потоком и возвращает все строки, подходящие под условия загрузки.

1. Если доступен подходящий целочисленный ключ или колонка `date NOT NULL`, приоритет выбора не меняется.
2. Если ни одна из оставшихся ступеней не подходит, используется однопоточное чтение во всех режимах, использующих общую эвристику.

### Сценарий 3. Не более одного запроса за границами (P1)

При многопоточном [инкременте](../../docs/glossary.md#term-increment) загрузчик получает верхнюю границу чтения и обе границы разбиения за одно обращение к источнику вместо двух. Цель — сократить число запросов к источнику.

**Независимая проверка**: для новой загрузки в каждом из четырёх режимов подсчитать вспомогательные запросы на стороне источника и проверить, какие границы они возвращают. Режим в таблице определяется до запроса: многопоточное чтение включено и найден кандидат на разбиение. Запрос может показать, что разбивать нечего.

| Режим чтения | Запросов | Что возвращает запрос |
|---|---:|---|
| Полное однопоточное | 0 | — |
| Полное многопоточное | 1 | Минимум и максимум колонки разбиения по таблице |
| Инкрементальное однопоточное | 1 | Максимум колонки [инкремента](../../docs/glossary.md#term-increment) по срезу |
| Инкрементальное многопоточное | 1 | Максимум колонки [инкремента](../../docs/glossary.md#term-increment), минимум и максимум колонки разбиения по одному срезу |

### Граничные случаи

- При [первичном наполнении](../../docs/glossary.md#term-bootstrap) сохранённой позиции нет. Верхняя граница определяется по всей исходной таблице без подсчёта строк. Пустая таблица не задаёт верхнюю границу.
- Если расчёт нижней границы выходит за минимум типа, сохраняется текущее правило: нижнее условие отсутствует и при поиске максимума, и при чтении.
- Отключение проверки `NOT NULL` не отменяет проверку существования и типа колонки. Строки с `NULL` в колонке [инкремента](../../docs/glossary.md#term-increment) не попадают в срез даже при первичном наполнении. Если все значения `NULL`, срез считается пустым.
- Повтор уже спланированной загрузки использует зафиксированные границы. Максимум колонки [инкремента](../../docs/glossary.md#term-increment) не пересчитывается. Если требуется разбиение, один запрос получает его границы внутри зафиксированного [окна чтения](../../docs/glossary.md#term-window).
- Если полученные границы не позволяют разделить чтение, загрузчик не отправляет дополнительный запрос. Он читает одним потоком или пропускает чтение пустого инкрементального среза.

<a id="требования"></a>
## Требования

- **FR-001**: Сохранить три ступени автоматического разбиения в прежнем порядке: одноколоночный целочисленный первичный ключ, целочисленная `NOT NULL`-колонка с одноколоночным уникальным ограничением, колонка `date NOT NULL`. Убрать ступень разбиения по календарным дням на основе `timestamp`. При отсутствии кандидата читать одним потоком. Поддержка `timestamp` как колонки [инкремента](../../docs/glossary.md#term-increment) остаётся.
- **FR-002**: Добавить булеву настройку `incremental.contract.check_not_null` со значением `true` по умолчанию.
  - При `true` до планирования новой [партии](../../docs/glossary.md#term-batch) проверять по JDBC-метаданным исходной таблицы, что колонка [инкремента](../../docs/glossary.md#term-increment) объявлена `NOT NULL`. Если это не подтверждено, отклонять планирование.
  - При явно заданном `false` не требовать подтверждения `NOT NULL`. Разработчик отвечает за то, чтобы у строк, которые должны быть загружены, было значение в колонке [инкремента](../../docs/glossary.md#term-increment).
  - При любом значении настройки не использовать `COUNT(*)` и `COUNT(col)` для проверки или определения пустоты.
- **FR-003**: Определять верхнюю границу новой [партии](../../docs/glossary.md#term-batch) по максимуму исходных строк, прошедших нижнее условие. Использовать одну и ту же нижнюю границу и оператор при определении максимума и при чтении: `>` при нулевом отступе или ненулевом целочисленном отступе, `>=` при ненулевом временном отступе с прежним выравниванием. Если нижней границы нет, определять максимум без нижнего условия. Строки с `NULL` в колонке [инкремента](../../docs/glossary.md#term-increment) не учитывать ни при определении границ, ни при чтении.
- **FR-004**: Отсутствие максимума считать пустым срезом. Не выполнять отдельную проверку, опустился ли максимум источника ниже [watermark](../../docs/glossary.md#term-watermark) или опустела ли ранее непустая таблица. Пустой срез не добавляет данных. Непустой срез читается по зафиксированным границам. [Watermark](../../docs/glossary.md#term-watermark) никогда не уменьшается и по-прежнему продвигается только по фактически прочитанным строкам.
- **FR-005**: Сохранить повторное использование зафиксированных границ и защиту от устаревшей фиксации. Повтор завершённой [партии](../../docs/glossary.md#term-batch) не обращается к источнику и не пишет данные повторно.
- **FR-006**: Выполнять не более одного вспомогательного агрегатного SQL-запроса к источнику за попытку загрузки таблицы. Выбирать только агрегаты, нужные для текущего режима. Для новой инкрементальной многопоточной загрузки получать все три значения в одном запросе с общим нижним условием из FR-003. Само чтение по-прежнему ограничивать полученной верхней границей. JDBC-метаданные и запросы чтения данных не входят в лимит.

### Ключевые понятия

- [Watermark](../../docs/glossary.md#term-watermark) — сохранённая позиция, от которой отсчитывается нижняя граница.
- [Окно чтения](../../docs/glossary.md#term-window) — диапазон между нижней границей с учётом отступа и максимумом выбранного среза.

<a id="критерии"></a>
## Критерии успеха

1. Для каждого проверенного регулярного запуска с нижней границей максимум ищется только среди строк за этой границей. При определении верхней границы выполняется ноль подсчётов строк.
2. Каждый проверенный пустой срез завершается успешно с нулём новых строк и неизменной позицией. Каждый проверенный непустой срез ниже сохранённой позиции загружается без ошибки регрессии и без отката позиции.
3. На каждом проверенном источнике таблица, где единственный прежний кандидат — `timestamp NOT NULL`, читается одним потоком без потери подходящих строк. Для таблиц с кандидатами оставшихся ступеней выбор колонки не меняется.
4. Для четырёх режимов новой загрузки наблюдается соответственно `0 / 1 / 1 / 1` вспомогательных агрегатных запросов. При повторе незавершённой загрузки таких запросов не больше одного. Переход на один поток после проверки границ не добавляет запросов.
5. Для одной и той же колонки без подтверждённого `NOT NULL` планирование отклоняется при отсутствующей настройке или при `true`. При `false` загружаются строки со значением позиции, подходящим под границы среза, а строки с `NULL` не загружаются. Лимит вспомогательных запросов не меняется.

<a id="границы"></a>
## Допущения и границы

- Сброс источника больше не распознаётся автоматически. Если новые значения окажутся ниже нижней границы, загрузка будет их пропускать без ошибки до ручного восстановления или появления значений в читаемом диапазоне.
- Правила расчёта [lookback](../../docs/glossary.md#term-lookback) и типы позиций не меняются. `check_not_null` влияет только на проверку колонки [инкремента](../../docs/glossary.md#term-increment), а не на критерии выбора колонки разбиения. [Полный срез](../../docs/glossary.md#term-full) и `act_snap` используют правила полного чтения из таблицы выше.
