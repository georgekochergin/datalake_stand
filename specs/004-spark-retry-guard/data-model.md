## Содержание

- [Состояния](#состояния)

## Состояния

- Вход: target и HTTP-адрес master. Connections разрешаются Airflow-обвязкой.
- Начальный снимок: обязательные массивы activeapps и completedapps. Запись приложения содержит непустые id, name и state.
- Исходные IDs: точное совпадение name с target в activeapps. Пустое множество разрешает submit.
- После однократного kill: исходный ID может оставаться активным WAITING/RUNNING до исчерпания бюджета.
- Завершение: каждый исходный ID отсутствует в activeapps и присутствует в completedapps с KILLED/FINISHED.
- Неизвестное состояние, некорректная структура, новый целевой ID в activeapps, исчезновение без свидетельства завершения и ошибки HTTP приводят к отказу.
- Новые IDs отслеживаются только в activeapps. Приложение, успевшее зарегистрироваться и завершиться между опросами, неотличимо от истории completedapps. Guard не заменяет контракт единственного владельца target.
- Постоянное состояние не добавляется. Реестр партий, CAS, watermark и process_id не изменяются.
