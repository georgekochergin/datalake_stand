## Сценарии и проверки

### US1: повтор после потери процесса задачи (P1)

Оператор стенда повторяет загрузку, не допуская нового запуска поверх прежнего зарегистрированного приложения этой таблицы.

Независимая проверка: оставить приложение целевой таблицы после отказа процесса задачи и повторить только загрузку.

1. При наличии прежних приложений система запрашивает их остановку и подтверждает завершение до новой отправки.
2. При отсутствии приложений система разрешает загрузку без поиска отдельных вычислительных процессов.
3. Повтор и ручная очистка состояния только задачи загрузки повторно выполняют защитную проверку.

### US2: запрет неподтверждённого запуска (P1)

При недоступном менеджере кластера или неподтверждённой остановке оператор получает отказ задачи, а не новую загрузку.

Независимая проверка: отключить выполнение остановки, сохранив успешный HTTP-ответ. Нового приложения не возникает.

### US3: предсказуемые повторы и диагностика (P2)

После отказа задачи выполняются максимум два повтора с задержкой пять минут. Поздние обработчики событий только логируют и не останавливают новые приложения.

Независимая проверка: проверить настройки всех задач обоих видов генерируемых DAG и вызвать обработчики после нового запуска.

### Краевые случаи

- Несколько прежних приложений одной таблицы, другая таблица, независимый кластер.
- Естественное завершение одновременно с остановкой.
- Исчезновение приложения без свидетельства завершения, неизвестное состояние, неверный ответ, исчерпание времени.
- Неожиданное новое активное приложение той же таблицы во время проверки — отказ. Приложение, зарегистрированное и завершившееся между опросами, этим правилом не обнаруживается.
- Старый скрипт продолжает финализацию метаданных после остановки Spark.

## Требования

- **FR-001**: все три вида загрузки обязаны проверять прежние приложения перед каждой отправкой.
- **FR-002**: область поиска определяется точным полным именем целевой таблицы без идентификатора попытки или контура.
- **FR-003**: каждому исходному приложению отправляется ровно один запрос остановки. Затем проверяется состояние.
- **FR-004**: завершение подтверждается менеджером кластера. Состояния KILLED и FINISHED допустимы. Одного успешного ответа на команду недостаточно.
- **FR-005**: любое неподтверждённое состояние запрещает новую отправку. Неожиданное новое приложение той же таблицы также запрещает отправку.
- **FR-006**: вся проверка ограничена 120 секундами, отдельный HTTP-запрос — пятью секундами и остатком общего бюджета, интервал — две секунды.
- **FR-007**: отдельные подключения отправки и управления настроены на один кластер без связующих полей. Тестовые подключения не обращаются к живому стенду.
- **FR-008**: все генерируемые задачи имеют два повтора с задержкой пять минут. Сохраняются один активный запуск DAG и единственный владелец таблицы.
- **FR-009**: обработчики событий только логируют. Существующее логирование FAILED сохраняется.
- **FR-010**: повтор загрузки сохраняет номер процесса, фиксированное окно, идентичность партии и гарантии watermark.

### Сущности

- Целевая таблица: полный идентификатор каталога, схемы и таблицы.
- Приложение: уникальный ID, имя целевой таблицы, состояние у менеджера кластера.
- Попытка задачи: каждый вызов загрузки, включая повтор и ручной Clear.

## Критерии успеха

- **SC-001**: во всех трёх операторах неподтверждённая остановка приводит к нулю новых отправок.
- **SC-002**: каждый повтор выполняет новую защитную проверку, даже если остальные задачи DAG не перезапускались.
- **SC-003**: успешная очистка не затрагивает другие таблицы и независимые кластеры.
- **SC-004**: проверки настроек подтверждают два повтора и пятиминутную задержку у всех генерируемых задач.
- **SC-005**: полный изолированный сценарий завершается с FAIL=0 и кодом 0. До этого реализация не считается принятой.

## Условия и границы

- Сохраняются client mode и текущий механизм отправки Spark.
- Единственный владелец таблицы и один активный запуск DAG — обязательные условия, а не распределённая блокировка.
- Workers не опрашиваются. Физическое завершение всех процессов, отмена commit и exactly-once не гарантируются.
- Обычный код driver может продолжаться. CAS защищает метаданные, но не все внешние действия.
- Зависший до регистрации driver, внешняя периодическая очистка и production-платформа вне задачи.
- Уточнения завершены предыдущим обсуждением: отдельный модуль, master-only, два подключения без extra-связей, один kill на ID, новый ID означает отказ. Открытых вопросов требований нет.
