# Контракт инкрементальной загрузки

## Требования

- YAML содержит обязательный `incremental.contract` с `source_column` и `position_type`.
- Канонический тип описывает позиции, а не схему Spark. Тип проверяется по JDBC без приведения источника.
- Генератор разрешает lookback до запуска: явное значение либо 0 для целых, 3 дня для даты, 3 часа/дня для timestamp по расписанию.
- Только инкрементальная загрузка получает один JSON-флаг `--incremental-config`, содержащий contract и разрешённый lookback. Старые флаги и YAML-формат не поддерживаются.
- Перед планированием новой партии тип сверяется до агрегатов. Перед повторным чтением проверяются сохранённый контракт и JDBC-тип без повторных COUNT/MAX планирования. Успешная партия не обращается к источнику.
- Full и act_snap независимы от контракта инкремента.
- Документация определяет канонический тип, содержит таблицу выбора и порядок работы трёх load-стратегий.

## Уточнения

Приняты в обсуждении: название поля `position_type`, вложенность `incremental.contract`, единый CLI `--incremental-config`; никаких алиасов старого контракта. Несовпадение типа — ошибка до записи, без автоматической миграции watermark.
