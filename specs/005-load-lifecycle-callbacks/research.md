## Выводы

- `TableLogOperator` и прежний callback FAILED используют один `meta.log_task`
  и PostgresHook. Отдельная задача не нужна для доступа к pg-meta.
- Callback не заменяет обязательный этап с собственными retries. Пользователь
  явно разрешил необязательную доставку событий, поэтому это ожидаемая смена гарантии.
- START на каждой попытке точнее отражает выполнение `load`, чем прежняя отдельная
  задача перед ожиданием слота. DDL не содержит номера попытки, его добавление вне задачи.
- Выбран общий callback с параметром статуса вместо трёх одинаковых функций.
- Исключение логируется только по типу: текст ошибки подключения может содержать секреты.
- Существующие функции/списки callbacks дополняются, а не заменяются.
