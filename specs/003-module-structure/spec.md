# Структура модулей загрузчика

## Требования

- Режимные контракты разделены: `IngestAppendOperator` заменяется на `IngestIncrementalOperator` и `IngestFullOperator`, каждый с фиксированным Spark-приложением; универсальный диспетчер по признаку режима не остаётся.
- Полный срез не получает реквизиты pg-meta: у его оператора нет параметров инкремент-конфигурации и реквизитов pg-meta; общее логирование START/END/FAILED и DAG-callbacks сохраняются на стороне Airflow для обоих режимов.
- Реквизиты pg-meta для реестра партий передаются одним явным контрактом: Airflow Connection `ingestion_meta` → строка подключения (DSN, `make_dsn`) → переменная окружения `INGESTION_META_DSN`; driver подключается `psycopg2.connect(dsn)`; отсутствие переменной — явная ошибка без печати секрета. Пять переменных `PG*` и пустой DSN устраняются.
- Общая инфраструктура операторов — пакет `ingestion/operators/` с единственной публичной точкой импорта `ingestion.operators`; общие helpers не знают типа источника, режима и слоя; публикация Asset — уровень raw; режимные операторы — raw+rdbms.
- Конфигурация сущности типизирована: `FullEntityConfig` и `IncrementalEntityConfig` с общими полями; `incremental_column` выводится из контракта, а не хранится независимым признаком; внешний YAML не меняется; единственная развилка генератора — выбор оператора по типу конфигурации.
- Общее логирование pg-meta и реестр партий инкремента разделены по модулям пакета `ingestion/meta/`; единый helper транзакций, порядок блокировок state→batch и CAS-ревизии сохраняются.
- Базовый контракт диалекта `RdbmsDialect` живёт в `ingestion/sources/rdbms/dialects/base.py` рядом с реализациями; контракты подключения остаются в `contracts.py`; публичные импорты сохранены re-export.
- DDL raw-таблиц переносится в область слоя (`ingestion/spark/raw/iceberg.py`); общий writer raw принимает очищенный DataFrame и число строк, не зависит от типа источника и режима; JDBC-reader получает явные фильтры и проекции и не определяет режим по optional-полям; подготовка окна и инкремент-статистика — в области инкремента.
- Неизменны: форматы YAML, DAG/task IDs, расписания, Assets, at-least-once append, watermark, lookback, фиксированное окно, переиспользование партии при retry, восстановление снимков, данные и DDL pg-meta, CLI spark-приложений.
- Пустые каталоги и контракты-заглушки под будущие типы источников и слои не создаются.

## Критерии приёмки

- Все потребители `IngestAppendOperator` переведены на конкретные операторы; замена публичного API документирована; остальные публичные импорты сохранены.
- Сгенерированные DAG-и импортируют операторы и callbacks только из `ingestion.operators`; смешанный пайплайн генерирует оба оператора с прежними IDs и зависимостями; snapshot-DAG создаётся только инкременту.
- Общий reader/writer не определяет режим через optional-поля; у полного среза в окружении driver нет реквизитов pg-meta.
- Генерация `--check` без расхождений; полный изолированный `./test/test.sh` — `FAIL=0`, exit 0; unit-проверки отражают новые контракты.
- `docs/architecture.md` и `docs/extending.md` обновлены вместе с реализацией; граф кодовой базы актуализирован финальным коммитом.
