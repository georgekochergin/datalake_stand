## Решение

Ревью от 17.11.2026: список источников валидируется до Docker-операций.
Все циклы оркестратора используют выбранный список. Порог памяти —
10 GiB на стек. Guard и PostgreSQL выполняются на каждом стеке параллельно
с двумя Spark-приложениями temporal/schema (по два ядра каждое).
Пул загрузок — шесть слотов. Увеличение Spark-ресурсов допускается только
при подтверждённом голодании. Проверки по указанию пользователя:
сначала bank, затем broker, затем bank+broker. Сравниваются фазовые метки
и полный бюджет каждого запуска.

Структурное уточнение: `test/pytest/` сохраняет глубину файлов бывшего
`test/unit/`, поэтому пути к production-модулям остаются прежними.
`pytest.ini` ограничивает сбор этой директорией. Runtime PostgreSQL
проверки переносятся отдельно в `test/e2e/check_meta.py`, выполняются в
Airflow с существующим PYTHONPATH. Вся Docker/shell/Spark-оснастка находится
в `test/e2e/`, рабочие деревья и логи остаются служебными в `test/`.
Старые entrypoint-обёртки не добавляются, действующие команды обновляются.

Конституция прочитана. Python без комментариев, изоляция от живого стенда,
ветка `georgekochergin/parallel-e2e`, мерж только пользователем.
Внешний согласованный план используется как исходное исследование, без
повторного профилирования. Текущие проверки Spark retry guard, добавленные
после плана, сохраняются и выполняются один раз.

1. Вынести профиль объёмов и подготовку тестового дерева в Python-модуль.
   Фильтровать конфигурацию источников, миграции и DAG. Проверять изменение
   retries через AST, не менять исходные production-файлы.
2. Параметризовать runtime-проверки источником, перенести статику в unit.
   Сократить только согласованные шаги, ускорить опрос и объединить SQL.
3. Перестроить shell-оркестратор: общие теги образов, однократная сборка,
   два фоновых стека, отдельные логи и очистка, агрегация статусов и времени.
4. Переименовать скилл в full-testing, обновить действующие ссылки и правила.

## Проверки

Доработка по ревью PR #71: независимый прогон дал 429 секунд при бюджете
420 секунд. Пост-проверки распараллеливаются после проверки реестра.
Temporal выполняется одновременно с guard в bank, с PostgresTests и
schema evolution в broker. Приложения temporal/schema ограничены двумя
ядрами Spark, таблицы и имена приложений различаются. Проверки здоровья
тестовых зависимостей опрашиваются чаще, Airflow — каждую секунду.
Лимит и покрытие не меняются. test-runner получает отдельный тестовый тег.
Приёмку необходимо повторить минимум дважды на тёплом кэше.

- Unit-тесты профиля, фильтрации, тестовых retries и статических контрактов.
- Shell syntax, Compose config обоих стеков, `git diff --check`.
- Итоговый параллельный e2e после увеличения памяти Docker VM.
  На старте работы доступно 16748032000 байт; это меньше порога.
- Граф обновляется по скиллу graphify перед коммитом. Коммит и публикация
  требуют отдельного разрешения.
