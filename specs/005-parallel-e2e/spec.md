## Требования

Уточнение по ревью от 17.11.2026: `--sources` выбирает один или два ключа
`ingestion/conf/sources.yaml`. Без флага используются все ключи, если их
не больше двух. Дубликаты и неизвестные имена запрещены. Все платформенные
проверки и повтор снимка выполняются на каждом стеке. Пул `ingest_loads`
увеличивается до шести слотов без изменения весов задач. Test-runner
не ждёт старта webserver через Compose. Фазы подготовки, подъёма и runtime
получают временные метки. Решением следующего ревью бюджеты разделены:
420 секунд для одного источника, 600 секунд для двух.

Уточнение пользователя: тестирование безопасности API sydafa удаляется
как ответственность отдельного проекта. Исходники тестов разделяются на
`test/pytest/` (запуск `python3 -m pytest` без поднятия стека) и `test/e2e/`
(все стековые сценарии, Docker, shell и помощники). Реальные PostgreSQL
проверки отделяются от mock-транзакций. Скилл документирует состав e2e
и правила расширения обоих видов тестов.

Основание — задача `docs/backlog.md` «Ускорить e2e-тестирование до 7 минут
параллельными стеками», DATARCH-2253 и согласованный план
`/Users/admin/ai_plans/dlh_poc/2026-11-13.1/plan.md`.

- Python-проверки выполняются отдельной командой перед e2e.
- Единственный полный сценарий одновременно проверяет bank и broker в
  изолированных стеках. Эволюция схемы остаётся для обоих источников.
- Операции наполнения ограничены профилем 10/10/100/100 строк.
- Удаляются только согласованные шаги 5а, 8, 12 и 13. Статика переносится
  в Python-проверки. Диалектно-независимые runtime-проверки выполняются один раз.
- Автоматические повторы отключаются только в копиях DAG тестового дерева.
  Production-настройки двух повторов через пять минут проверяются статически.
- Память Docker VM проверяется до запуска: минимум 10 GiB на выбранный стек.
- Полная длительность e2e измеряется, включая сборку из тёплого кэша,
  подготовку, выбранные стеки и очистку. Лимит — 420 секунд для одного
  источника, 600 секунд для двух. Холодная сборка
  не используется для оценки бюджета.
- При превышении бюджета после изменений требуется оптимизация теста.
  Повышать лимит или молча сокращать покрытие нельзя.
- Отладочный режим `--verify --sources <источник>` требует ровно один источник.

Уточнения пользователя от 2026-11-17: отключение повторов в тестовых DAG
согласовано; открытый пункт 4 старого плана неактуален. Повторный базовый
замер для поиска узких мест не нужен.

## Приёмка

- `python3 -m pytest`: код 0.
- `./test/e2e/shell/test.sh --sources bank`: код 0, полный сценарий, замер ≤420 секунд.
- `./test/e2e/shell/test.sh --sources bank broker`: код 0, оба стека без ошибок, общий замер ≤600 секунд.
- После оптимизаций — минимум два последовательных полных прогона каждого режима на тёплом кэше.
- Ошибки и сигналы не оставляют ресурсы тестовых стеков и рабочие деревья.
- Скилл тестирования описывает оба шага, измерение и обязательную оптимизацию.
