# Контракт вспомогательных DAG-ов act_snap

## Требования

- Конфигурация `incremental.act_snap` заменяет `full_snapshot` без совместимости со старым ключом.
- Снимок имеет собственные `schedule`, `tags`, `spark.jdbc_partitioning`, `airflow.pool.name/slots`; значения основной сущности не наследуются.
- FQN и источник берутся у родителя. Ключи `fqn`, `entities`, `incremental`, `catchup`, `max_active_runs` запрещены внутри `act_snap`.
- Снимочный DAG существует для каждой инкрементальной сущности, даже без блока настроек. Catchup выключен, число одновременных запусков фиксировано проектом: один.
- Публикация Asset — постоянная задача PythonOperator. Для обычной загрузки проверок нет; для снимка одна произвольная строка должна принадлежать текущему процессу. Пустая таблица и чужой процесс означают пропуск, ошибка чтения — ошибку задачи.
- Локальный файловый маркер Spark удаляется. Retry сохраняет сверку автора по свойству Iceberg.
- Исполнитель вспомогательного снимка называется `IngestActSnapOperator` в соответствии с именем конфигурации, тегом и Spark-модулем.
- URI снимка: `raw://<source_id>/<fqn>/act_snap`.

## Критерии приёмки

Валидация отвергает старые и запрещённые ключи; независимые настройки отражаются в сгенерированном коде; unit-проверки покрывают три исхода проверки публикации и ошибку чтения; e2e проверяет новую структуру и публикацию снимка.
