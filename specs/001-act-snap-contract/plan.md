# План реализации

## Конституция и уточнения

Изменения выполняются в текущей ветке PR, без изменения конституции. Все решения о конфигурации и URI согласованы с пользователем. Конституция содержит устаревшее правило финального коммита графа, противоречащее обновлённому AGENTS.md; изменение конституции требует отдельного PR и не входит в задачу.

## Проектирование

- Общий базовый dataclass содержит только schedule и tags; PipelineManifest расширяет его полями основного DAG-а, ActSnapConfig — вложенными SparkConfig и AirflowConfig. Основной YAML не расширяется.
- Общие парсеры вложенных настроек обеспечивают одинаковые пути YAML и строгие типы. Снимок получает независимые defaults.
- PythonOperator вызывает общую функцию публикации. Опциональное условие снимка читает `__process_id LIMIT 1` через существующее подключение Trino; SQL-ошибки не маскируются.
- Spark отвечает только за атомарную запись; Airflow — за проверку опубликованных данных и событие Asset после log_end.
- Обновляются архитектура, демо, обзор README, unit- и e2e-проверки.

## Проверки

Unit-тесты, статическая валидация манифестов и сгенерированного Python, изолированный e2e по скиллу e2e-testing. Невыполненные проверки явно фиксируются.
# Завершение проверки контракта

Пункты 3–5 плана от 2026-11-08 выполняются поверх влитого PR #49.
Функциональный контракт не меняется; расширяется интеграционное покрытие.
Управляемые SQL-проекции через реальные JDBC MSSQL/Oracle моделируют
последовательность видимых наборов строк без административного доступа к
sydafa. Порядок коммитов двух транзакций этим тестом не доказывается.
Сбои инъецируются вокруг реальных операций Iceberg/pg-meta; прежний writer
считается остановленным. Fencing и доказательство одновременных JDBC-сессий
не входят в проверку. Полный и частичный Clear проверяются через API Airflow.
Документация следует действующему act_snap, а не устаревшим именам внешнего
плана; граф включается в соответствующие коммиты по AGENTS.md.
