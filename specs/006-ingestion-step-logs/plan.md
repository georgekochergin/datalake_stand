# План диагностики загрузки

- Airflow: выделить этапы guard и submit. Форматировать реальный `argv` на границе маскирования Spark provider, не меняя запуск процесса.
- Spark: включить Python INFO и выводить SQL, метаданные и результаты в местах, где запросы уже выполняются. Использовать факты JDBC без повторного чтения источника.
- pg-meta: логировать SQL перед вызовом, брать фактические строки из `RETURNING`, выводить их после `commit`. Сохранить порядок блокировок и проверку ревизии.
- Проверки: тестировать маскирование, порядок колонок и ошибку фиксации без стенда. На стенде проверять фактические логи через Airflow API и сохранить примеры выгрузок отдельно от репозитория.
