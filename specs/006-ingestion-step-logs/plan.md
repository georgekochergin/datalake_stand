# План диагностики загрузки

- Airflow: выделить этапы guard и submit. Форматировать реальный `argv` на границе маскирования Spark provider, не меняя запуск процесса.
- Spark: включить Python INFO и выводить SQL, метаданные и результаты в местах, где запросы уже выполняются. Форматировать только копию SQL для лога. Использовать факты JDBC без повторного чтения источника.
- pg-meta: подставлять параметры в отображаемый SQL средствами драйвера перед вызовом. Не менять запрос и параметры в `execute`. Брать фактические строки из `RETURNING` и выводить их после `commit`. Сохранить порядок блокировок и проверку ревизии.
- Проверки: тестировать маскирование, порядок колонок и ошибку фиксации без стенда. На стенде проверять фактические логи через Airflow API и сохранить примеры выгрузок отдельно от репозитория.
