# Диагностика шагов загрузки

## Цель

По логам Airflow и Spark оператор должен видеть, что именно прочитано из источника и что сохранено в Iceberg и pg-meta.

## Требования

- Отделять Spark guard от запуска Spark. Показывать фактическую команду по флагам, без реквизитов подключения и произвольных значений Spark-конфигурации.
- Выводить вспомогательные SQL и результаты. `MAX/COUNT` относится ко всему источнику, `MIN/MAX` — к запросу чтения. Если запрос пропущен, объяснять почему.
- Показывать вызовы JDBC-метаданных, свойства колонок в порядке следования и результат выбора колонки для параллельного чтения.
- Показывать SQL и параметры операций pg-meta. Выводить записанную строку только после фиксации. Отличать отсутствие изменений от неуспешной транзакции.
- Не менять границы загрузки, порядок блокировок и число запросов или действий Spark.

## Приёмка

Проверить первый и следующий запуски `transactions` и полный срез `deals` на `bank` и `broker`. Для `deals` должно быть видно отключение партиционирования вместо SQL `MIN/MAX`. Операций инкрементального реестра быть не должно.
