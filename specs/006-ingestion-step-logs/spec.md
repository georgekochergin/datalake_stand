# Диагностика шагов загрузки

## Цель

По логам Airflow и Spark оператор должен видеть, что именно прочитано из источника и что сохранено в Iceberg и pg-meta.

## Требования

- Отделять Spark guard от запуска Spark. Показывать копируемую shell-команду по флагам с JDBC URL без секретов и именем пользователя. Пароль показывать как `***` и заменять перед ручным запуском. DSN pg-meta и значения произвольной Spark-конфигурации брать из переменных.
- Выводить вспомогательные SQL многострочно, сохраняя вложенность, и показывать результаты. `MAX/COUNT` относится ко всему источнику, `MIN/MAX` — к запросу чтения. Если запрос пропущен, объяснять почему.
- Показывать вызовы JDBC-метаданных, свойства колонок в порядке следования и результат выбора колонки для параллельного чтения.
- Показывать каждый SQL-запрос отдельным блоком. Для pg-meta подставлять параметры только в копию для лога, не меняя выполнение запросов. Отмечать неявный `BEGIN` и подтверждённый `COMMIT` или `ROLLBACK`. Выводить записанную строку только после фиксации.
- Не менять границы загрузки, порядок блокировок и число запросов или действий Spark.

## Приёмка

Проверить первый и следующий запуски `transactions` и полный срез `deals` на `bank` и `broker`. Для `deals` должно быть видно отключение партиционирования вместо SQL `MIN/MAX`. Операций инкрементального реестра быть не должно.
